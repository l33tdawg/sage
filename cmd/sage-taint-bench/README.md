# sage-taint-bench

Measures the provisional constants of the governance taint RFC ([#460](https://github.com/l33tdawg/sage/issues/460)).

**This is a stand-in harness.** It models the RFC constants over real Badger, using the planned key layouts and unit costs with Badger opened the same way as `store.NewBadgerStore`. The app-v30 implementation now exists, but this command does not execute it and has no AppHash, CometBFT, SQL mirror or live node. Memory content and existing index writes are represented only by the keys the fixture writes. Each result says so in `stand_in` and `notice`; use the real-code tests and CI gates for release evidence.

The real store/scope/admission/expansion counterpart is
[`sage-taint-realbench`](../sage-taint-realbench/README.md). It emits a
cross-architecture deterministic digest and AppHash evidence while still
leaving live CometBFT, SQL mirror and restart/state-sync proof to their dedicated
gates.

## Running it

```sh
make bench-taint BENCH_ARGS="-profile smoke -data-dir /path/on/real/disk"
```

| flag | meaning |
|---|---|
| `-profile` | `smoke` (about a minute) or `full` |
| `-data-dir` | parent of the disposable Badger directory, removed afterwards. Use a real disk, not tmpfs |
| `-require-arch` | `amd64` or `arm64`. Fails unless `GOARCH` and `uname -m` both match |
| `-repeats` | timing repeats per scenario |
| `-out` | result path. `make bench-taint` writes `bench/results/taint-<sha>-<goarch>.json` |
| `-node-copy` | read-only counts from a **copy** of a stopped node's Badger directory. Never point it at a running node |
| `-receipt` | with `-node-copy`, `-node-label` and `-snapshot-date`, writes a counts-only receipt and skips the benchmark. It records the label, never the path |

The `Taint Benchmark` workflow runs the same command on `ubuntu-24.04`, fails unless the runner is x86_64 and amd64, and uploads the JSON as an artifact.

## Comparing arm64 and amd64

Units, generated bytes, estimates and the tombstone accounting are deterministic, so `deterministic_digest` must be identical on both architectures for the same profile. A different digest means a constant does not hold; diff the `deterministic` objects to find which one. Timings are expected to differ, and the disk cross-check for tombstones stays out of the digest because compressed SST sizes are not a consensus value.

## What it reports

- **`constants.unit_ceiling`:** request units against 65,536. Three cases: a walk over 16-parent ancestries of 64-signer records whose memberships are all cleared or a stale generation, flat pre-app-v30 records with 64 coauthors, and a wide frontier. Each also proves the ceiling is exact: a ceiling equal to demand succeeds and one below it fails closed.
- **`constants.block_write_ceiling`:** bytes counted against 4 MiB, for the full admission block, the worst mixed blocks and a cleanup block. `E` bounds taint keys plus the `memprov` marker and both lineage directions from the submit's shape and the protocol limits, before execution, and the same `E` drives selection, the block verdict and each tx's reservation. Every tx asserts actual bytes ≤ `E`. Over-ceiling blocks are still executed so their size is visible, and are marked `process_proposal: reject`; `txs_selected_by_prepare_proposal` shows how many would have been selected. Memory content and existing index writes stay out, because the raw block limit already covers them.
- **`constants.tombstone_constant_bytes`:** taken from the point at which Badger refuses a transaction, plus the 8-byte version suffix.
- **`constants.expansion`:** how many expansion txs and memberships fit in a block.
- **`real_node_counts`:** over-cap IDs, adopted records and app-v30 migrated markers, only when `-node-copy` is given. Otherwise they are reported as not measured.
